# clw security &amp; correctness audit — 2026-06-09

> Full-crate read-audit of `clw` (all 11 crates). Driven from the CoreLink
> techlead seat. This branch (`fix/clw-audit-2026-06-09`) addresses the HIGH/MED
> findings + the polish LOWs in one consolidated change; the deferred items below
> are tracked, not silently dropped.

## Verdict

Well-built phase-1 — frozen contract, BLAKE3 integrity actually verified, real
test discipline (unit + wiremock + binary e2e + live conformance + proptest),
token redaction, clean prod-path panic hygiene. The findings were boundary gaps,
not sloppy code.

## Fixed in this branch

| # | Sev | Finding | Fix |
|---|-----|---------|-----|
| H1 | HIGH→CRIT | `hydrate` did `dest.join(path)` with manifest-controlled paths — absolute / `..` / symlink-escape wrote **outside** `dest` | `clw-types::validate_rel_path` + `validate_symlink_target` enforced in `Manifest::from_bytes`; `hydrate` re-validates (defense-in-depth) |
| H2 | HIGH | `~/.clw/config.toml` (plaintext PAT) written umask-default (often `0644`) | written `0600`; `~/.clw` `0700`; cache root `0700` |
| M1 | MED | avoidable `unsafe` raw-pointer cache borrow in `hydrate` | direct sync cache access (the `snapshot` pattern); **zero `unsafe`** in `clw-hydrate` |
| M2 | MED | PAT sent over plaintext if `endpoint=http://` | `HttpClient::new` requires `https://` (loopback excepted for dev/tests) |
| M3 | MED | `clw run` key omitted the toolchain → stale replay after e.g. a `cargo` upgrade | tool-identity (content digest of `command[0]`) folded into the key; domain `v1`→`v2` |
| M4 (hydrate half) | MED | whole file buffered in memory on hydrate | streams each chunk straight to the temp file |
| M5 | MED | no jitter on retry backoff (synchronized herds) | jittered backoff (no new dep) |
| LOWs | LOW | deprecated `home_dir`; fragile fake-TOML parser; `--token` in argv; no `--concurrency` | non-deprecated `home_dir`; parser documents its minimal-TOML subset + ignores inline comments after quoted values; `--token` help warns of process-list visibility; `--concurrency` global flag (default 8) |

All changes are std-only (no new dependencies), 4 disjoint work-packages + a
fifth for the LOWs, each with added tests.

## Deferred — tracked follow-ups (NOT done here, on purpose)

1. **M4 (snapshot half) — stream large files on `snapshot`.** `snapshot` still
   `std::fs::read`s whole files. The clean fix (FastCDC `StreamCDC`) touches the
   **frozen chunking contract** and must be proven boundary-identical to the
   current `FastCDC` (else cross-snapshot dedupe breaks). Deserves its own change
   + an equivalence proptest. MED, scale-only, not a correctness/security bug.
2. **L4 — halve snapshot requests (drop the `exists` HEAD before `put`).** Today
   each chunk is `exists` + `put` (2 requests) which doubles pressure under the
   free-tier rate limit. Halving it cleanly requires `CasTransport::put` to
   report created-vs-existed — a change to the **frozen `clw-types` trait** that
   ripples to every test fake. Worth doing, but as a focused contract change.
3. **L5 — ref lifecycle (`clw rm` / `prune` / list-all).** You can create refs
   but not delete/list them. Needs an `AcTransport::delete` (frozen-trait
   addition) **and** server-side `DELETE /v1/ac/...` support — confirm the server
   capability first. This is a feature, not a fix.
